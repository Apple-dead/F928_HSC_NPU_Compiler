# 回归测试说明

## 1. 测试入口

在工程根目录运行：

```bash
python ./test/run_regression.py
```

默认使用 Windows 构建入口：

```text
build.bat
```

可以显式选择构建脚本：

```bash
python ./test/run_regression.py --os windows
python ./test/run_regression.py --os linux
```

`--os windows` 使用 `build.bat`，`--os linux` 使用 `bash ./build.sh`。

## 2. 用例目录约定

`test/run_regression.py` 会遍历 `./test` 下除以下目录以外的所有子目录：

```text
tools
error
__pycache__
```

每个子目录都是一个完整回归用例，例如：

```text
test/model1/
test/model2/
...
```

每个用例目录必须包含统一命名的文件：

```text
model.pt2
npu_config.py
intr_move.json
all.coe
```

可选文件：

```text
all.coe.map.txt
```

`all.coe.map.txt` 不参与自动判定，只在发生错误时辅助人工排查。

## 3. npu_config.py 路径约定

用例自己的 `npu_config.py` 应使用从工程根目录出发的相对路径，例如：

```python
MODEL_PATH = "./test/model1/model.pt2"
INTR_MOVE_PATH = "./test/model1/intr_move.json"
```

回归脚本只会把用例目录中的 `npu_config.py` 复制到：

```text
python/npu_config.py
```

不会复制 `model.pt2` 或 `intr_move.json`。这能保证模型和截位配置始终由 fixture 自己持有，避免污染工程根目录。

## 4. 执行流程

对每个 `test/modelX` 用例，脚本执行：

```text
1. 检查 model.pt2 / npu_config.py / intr_move.json / all.coe 是否存在。
2. 执行 build clean。
3. 备份原 python/npu_config.py，并将用例 npu_config.py 复制过去。
4. 执行 build。
5. 调用 test/tools/diff.py 比较 test/modelX/all.coe 和 target/all.coe。
6. 记录通过或失败。
```

无论测试结果如何，脚本最后都会：

```text
1. 恢复原 python/npu_config.py。
2. 执行 build clean。
```

## 5. 判定规则

测试通过条件：

```text
target/all.coe 与 test/modelX/all.coe 完全一致
```

如果 build 失败、必需文件缺失或 COE 不一致，该用例失败。

## 6. 错误日志

失败日志写入：

```text
test/error/
```

若需要清理这些错误日志，可以在工程根目录运行：

```bash
./build.sh distclean
```

或在 Windows cmd 中运行：

```bat
.\build.bat distclean
```

日志名包含失败用例名和时间戳，例如：

```text
test/error/model1_20260708_203012.log.txt
```

当 COE 不一致时，日志会包含：

```text
首个不同行号
该行 expected / actual 内容
test/tools/diff.py 的输出
fixture all.coe.map.txt 和 target/all.coe.map.txt 的路径提示
```

这样可以先用日志定位差异，再结合 map 文件人工检查内存布局。

## 7. 成功输出

全部用例通过时，脚本最后输出类似：

```text
[SUMMARY] passed=1 failed=0 total=1
```
