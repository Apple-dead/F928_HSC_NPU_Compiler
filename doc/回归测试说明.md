# 回归测试说明

本文档说明 `test/run_regression.py` 的测试用例组织方式和执行流程。

## 1. 测试入口

在工程根目录运行：

```bash
python ./test/run_regression.py
```

默认按 Windows 环境执行，也就是调用 `build.bat`。可以手动指定构建脚本：

```bash
python ./test/run_regression.py --os windows
python ./test/run_regression.py --os linux
```

其中：

- `--os windows` 调用 `cmd /c build.bat`。
- `--os linux` 调用 `bash ./build.sh`。

脚本默认扫描：

```text
test/model1
test/model2
...
test/model10
```

只运行实际存在的 `modelN` 目录。比如当前只有 `test/model1`，脚本只测试 `model1`，不会因为缺少 `model2` 到 `model10` 而报错。

## 2. 单个测试模型目录

每个 `test/modelN` 目录必须包含：

```text
model.pth
model.py
npu_config.py
intr_move.json
image.coe
all.coe
all.coe.map.txt
instr.txt
instr.asm
```

其中：

- `model.pth` / `model.py` 是测试模型输入。
- `npu_config.py` / `intr_move.json` 是该模型对应的编译配置。
- `image.coe` 是该模型对应的输入数据。
- `all.coe`、`all.coe.map.txt`、`instr.txt`、`instr.asm` 是已经验证通过的 golden 产物。

## 3. 文件映射规则

脚本每次运行时会读取当前选择的构建脚本中的模型文件名。

Windows 模式读取 `build.bat`：

```bat
set "MODEL_NAME=..."
set "MODEL_PY_NAME=..."
```

Linux 模式读取 `build.sh`：

```bash
MODEL_NAME="..."
MODEL_PY_NAME="..."
```

然后把测试目录中的文件复制到当前编译器实际使用的位置：

```text
test/modelN/model.pth      -> model/<MODEL_NAME>
test/modelN/model.py       -> model/<MODEL_PY_NAME>
test/modelN/npu_config.py  -> python/npu_config.py
test/modelN/intr_move.json -> data/intr_move.json
test/modelN/image.coe      -> coe/image.coe
```

这样即使以后构建脚本中硬编码的模型文件名改变，测试脚本也会跟随当前构建脚本配置。

## 4. 执行流程

对每个存在的 `modelN`，脚本执行：

```text
1. 检查 test/modelN 下测试文件是否完整。
2. 备份当前工作区输入文件。
3. 将 test/modelN 下的输入文件复制到构建脚本使用的位置。
4. 执行所选构建脚本的 clean。
5. 执行所选构建脚本。
6. 使用 test/tools/diff.py 对比 golden 产物和新生成产物。
7. 所有测试结束后恢复运行前的输入文件。
8. 如果全部测试通过，再执行一次所选构建脚本的 clean 清理构建产物。
```

Windows 模式下对应命令为：

```text
cmd /c build.bat clean
cmd /c build.bat
```

Linux 模式下对应命令为：

```text
bash ./build.sh clean
bash ./build.sh
```

目前比较的产物为：

```text
target/all.coe         <-> test/modelN/all.coe
target/all.coe.map.txt <-> test/modelN/all.coe.map.txt
data/instr.txt         <-> test/modelN/instr.txt
data/instr.asm         <-> test/modelN/instr.asm
```

全部一致时打印：

```text
modelN test passed
```

## 5. 失败日志

如果测试文件缺失、构建失败或产物对比失败，脚本会继续处理后续测试模型，并在：

```text
test/error/
```

下生成日志，例如：

```text
test/error/model1_20260707_153012.log
```

日志中会记录：

- 当前测试模型名。
- 构建脚本中解析到的 `MODEL_NAME` / `MODEL_PY_NAME`。
- 选择的目标系统：`windows` 或 `linux`。
- 构建命令的 stdout / stderr。
- 不一致产物的 `diff.py` 输出片段。

## 6. 注意事项

- `test/tools/diff.py` 是文本 diff 工具，适合比较当前 `.coe`、`.txt`、`.asm` 这类文本产物。
- 测试脚本始终会恢复运行前的输入文件。
- 如果全部测试通过，脚本会自动运行所选构建脚本的 clean 清理构建产物。
- 如果测试失败，脚本不会执行最终 clean，会保留构建现场以便排查。
- 如果新增 `model2`、`model3` 等测试用例，只需按相同目录结构放入 `test/modelN`，不需要修改脚本。
