# 全连接算子说明

## 1. 前端解析

PT2 前端遇到 `aten.flatten.using_ints` 时直接透传 value 映射，不写入 `data/model_ir.json`，也不计入 `INFER_PARSE_OP_LIMIT`。

例如：

```text
conv2d -> relu -> flatten -> linear
```

当 `INFER_PARSE_OP_LIMIT = 3` 时，导出的有效 IR op 是：

```text
conv2d -> relu -> linear
```

## 2. FULL 执行语义

一个 `FULL` 指令只计算一个全连接输出元素。若 `linear.out_features = 10`，编译器会生成 10 次 FULL。

每次 FULL 的地址规则：

```text
input_addr  = 上一层输出基址，所有输出共用
weight_addr = 当前输出元素对应的权重块起始地址
output_addr = linear 输出基址 + output_index
```

FULL 输出由 NPU 保证为 signed int8，因此 `linearN_out` 按 byte 紧密排列。

## 3. FULL 输入字数

RFULL 中的输入字数按上一层输出的物理 storage footprint 计算：

```text
input_storage_bytes = aligned_channels * storage_height * storage_width
input_words = input_storage_bytes / 4
```

`linear.in_features` 仍按模型逻辑 shape 校验：

```text
linear.in_features == channels * height * width
```

## 4. 权重重排

前端导出的 `linearN_weight.txt` 保持 PyTorch OI 逻辑布局：

```text
[out_features, in_features]
```

生成 `linearN_params.coe` 时，编译器把每个输出元素的权重扩展到上一层输出的物理布局：

```text
[aligned_channels, storage_height, storage_width]
```

补零规则：

- 逻辑通道数不是 4 的倍数时，补齐到 4 的倍数，补出的通道权重全为 0。
- 逻辑 H/W 小于 storage H/W 时，padded 行列权重全为 0。

单个输出元素的权重写入顺序：

```text
for channel_group in 4-channel groups:
  for row in storage_height:
    for col in storage_width:
      emit ch0, ch1, ch2, ch3
```

若该 linear 有 bias，则在该输出元素的权重块后紧跟一个 int32 bias。

## 5. 截位配置

全连接截位配置来自 `intr_move.json`：

```json
{
  "FULL_MOVE_BY_INDEX": {
    "1": 512
  }
}
```

编号表示当前 IR 中第 N 个 linear，从 1 开始。move 会转换为 RFULL 的 `start_position`，规则与 conv 相同。
