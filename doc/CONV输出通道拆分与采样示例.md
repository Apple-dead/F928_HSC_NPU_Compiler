# 2026-11-04：CONV 输出通道拆分与采样示例

> 2026-11-05 更正：所有算子的输入和输出都应采用 8 通道分组布局，见 [统一布局说明](8通道分组布局.md)。下文记录的两个旧采样示例，其逐像素全通道参考输出存在排列问题，按用户要求暂时保留；不能据此判断当前编译器的布局。

当前硬件每次 CONV 最多计算 8 个输出通道。RCONV1 的输出通道字段虽然占 5 bit，但不能据此认为硬件能一次完成 32 个输出。旧的“一次最多 32 通道”代码和配置注释已修正。

拆分由 `python/memory_layout.py` 统一定义，memory plan 和权重导出共用规则：

- 6in16out → 两次 6in8out；17 个输出 → 8 + 8 + 1。
- 每次使用相同输入地址，RCONV1 保留完整输入通道数，输出通道数为本次有效通道数。
- 输出按连续的 H×W×8 字节块排列，第二组输出地址为 `base + H*W*8`。最后一组 feature 补到 8 通道。
- 参数只存有效输出记录，每条记录为补齐输入通道后的权重，以及可选的 int32 小端 bias 和 4 个零字节。参数地址按记录长度推进，不插入虚拟输出记录。
- 融合 ReLU 配置为本次有效输出通道数；所有 CONV 完成后再执行层级 DSMP。
- FULL 参数导出识别上游 CONV 的分组布局，使权重顺序与实际输入一致。

此前的软件回归验证覆盖了 1/5/8/9/16/17/32 输出、有无 bias、寄存器解码、参数偏移和逐组参考计算，以及 1024 输出的 128 次拆分、stride=2 调度和 FULL 参数排列。

旧版 `conv_relu_1x1_13x13_6in16out` 示例的指令使用一次 16 输出，当前编译器会生成两个 8 输出 pass。

新增示例：

|目录 / ZIP 名称|输入 H×W×C|输出 H×W×C|参考计算|
|---|---|---|---|
|downsample_16x16_16channels|16×16×16|8×8×16|`y[h,w,c] = x[2*h,2*w,c]`|
|upsample_16x16_16channels|16×16×16|32×32×16|`y[h,w,c] = x[h//2,w//2,c]`|

两个例子共享相同的随机 signed int8 输入，种子为 20261104。每个例子都有 aligned64 和 unaligned64 两版，各包含 8 条指令（6 条 CFG、1 条 DSMP/USMP、1 条 END）。这两个独立采样例子沿用既有采样示例的数据约定：输入为通道组 → H → W → 8 通道，输出为 H → W → 全部 16 通道；该输出约定与 CONV 的逐 pass 输出块分别在各自 memory plan 中注明。

独立 DSMP 示例从后端执行计划开始，无需额外的前端 IR 算子。

软件参考、逐字节地址对应、寄存器编码、COE/BIN/MEM 一致性已经核对；尚未执行 RTL 仿真。
