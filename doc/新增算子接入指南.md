# 新增算子接入指南

本文说明后续向编译器加入新算子时，需要改哪些位置，以及各层之间如何传递信息。

## 1. 总体流程

新增算子通常要经过以下链路：

```text
PT2 frontend
  -> data/model_ir.json
  -> generate_memory_plan.py
  -> data/memory_plan.json
  -> generate_instr.py + operator/<op>/<op>.py
  -> data/instr.asm / data/instr.txt
  -> params_to_bram_coe.py
  -> coe/*.coe
  -> merge.py
  -> target/all.coe
```

如果新算子只是 shape/view 类操作，例如 `flatten`，可能不需要生成指令，也不需要 runtime buffer，但仍需要在 memory plan 中更新 IR value 到 tensor/shape 的映射。

如果新算子有参数，例如 `linear`，还需要生成参数 txt、规划 init region，并在 `params_to_bram_coe.py` 中写入对应参数 COE。

## 2. 前端 IR

文件：

```text
python/frontend/ir_schema.py
python/frontend/pt2_frontend.py
```

需要做：

1. 在 `SUPPORTED_IR_OPS` 中加入 IR op 名称。
2. 如果后端已经支持该算子，在 `BACKEND_SUPPORTED_OPS` 中加入名称。
3. 在 `pt2_frontend.py` 的 `TARGET_TO_OP` 中加入 PT2 aten target 到 IR op 的映射。
4. 在 `export_model_ir()` 中补充该 op 的属性导出逻辑。

参数类算子还要在前端导出参数 txt，例如 `linear` 已经导出：

```text
data/model_params/linearN_weight.txt
data/model_params/linearN_bias.txt
```

## 3. Memory Plan

文件：

```text
python/generate_memory_plan.py
```

核心扩展点：

```python
UNIT_PARSERS
UNIT_PLANNERS
```

### 3.1 IR op 转 execution unit

新增一个 parser 函数，把 `model_ir.json` 中的 op 转为后端 execution unit：

```python
def parse_xxx_unit(ops, index, units):
    op = ops[index]
    return (
        {
            "op_type": "xxx",
            "layer": op["name"],
            "input": op["input"],
            "output": op["output"],
            # op-specific fields...
        },
        index + 1,
    )
```

然后注册：

```python
UNIT_PARSERS["xxx_ir_op"] = parse_xxx_unit
```

### 3.2 execution unit 转 memory plan stage

新增一个 planner 函数，负责：

1. 读取输入 IR value 对应的 tensor 和 shape。
2. 校验硬件约束。
3. 分配 init/runtime region。
4. 创建 `plan["tensors"]` 条目。
5. 追加 `plan["execution_plan"]` stage。
6. 注册输出 IR value 的 tensor 和 shape。

推荐骨架：

```python
def plan_xxx_unit(plan, unit, value_tensors, value_shapes):
    input_name, input_tensor_name, input_shape = require_input_value(unit, value_tensors, value_shapes)
    input_tensor = plan["tensors"][input_tensor_name]

    # allocate regions / build execution_plan stage

    register_value(
        value_tensors,
        value_shapes,
        unit.get("output"),
        output_tensor_name,
        height=...,
        width=...,
        channels=...,
        aligned_channels=...,
    )
```

然后注册：

```python
UNIT_PLANNERS["xxx"] = plan_xxx_unit
```

### 3.3 shape/view 类算子

`flatten` 这类算子通常不分配新内存，只更新 value 映射。可以让输出 value 复用输入 tensor，但更新 shape metadata：

```python
value_tensors[output] = input_tensor_name
value_shapes[output] = new_shape
```

注意：如果后续硬件要求 flatten 后的数据布局不同，不能只做 view，需要显式规划搬运或重排。

## 4. 指令生成

文件：

```text
python/generate_instr.py
operator/<op>/<op>.py
```

核心扩展点：

```python
OPERATOR_PATHS
OP_PLAN_BUILDERS
SINGLE_OPERATOR_STAGES
stage_operator_sequence()
```

### 4.1 新增 operator 文件

新增目录：

```text
operator/xxx/xxx.py
```

必须提供：

```python
def compile_op(op_plan, memory_plan) -> list[str]:
    ...
```

这个函数只负责把单次 NPU 操作翻译为汇编片段，不负责全局地址规划。

### 4.2 注册 operator

在 `generate_instr.py` 中加入：

```python
OPERATOR_PATHS["xxx"] = PROJECT_ROOT / "operator" / "xxx" / "xxx.py"
```

如果一个 execution stage 只对应一个 operator，加入：

```python
SINGLE_OPERATOR_STAGES["xxx"] = ["xxx"]
```

如果一个 stage 会展开成多条 operator，或需要按 layer 级别而不是 split 级别生成指令，则在 `stage_operator_sequence()` / `layer_operator_sequence()` 和对应 op plan builder 中新增分支。

### 4.3 组装 op_plan

新增：

```python
def build_xxx_op_plan(layer_plan, split, common, intr_moves):
    common.update(split["xxx"])
    return common
```

并注册：

```python
OP_PLAN_BUILDERS["xxx"] = build_xxx_op_plan
```

## 5. 汇编器

文件：

```text
python/assembler.py
```

如果新算子引入新的汇编 mnemonic 或专用寄存器，需要更新：

```python
SPECIAL_REGISTER_CODE
COMPUTE_OPCODE
COMPUTE_OPERAND_COUNT
```

例如池化：

```python
SPECIAL_REGISTER_CODE["AVGPOOL_P_1"] = 0x0A
SPECIAL_REGISTER_CODE["AVGPOOL_P"] = 0x0B
COMPUTE_OPCODE["AVGPOOL"] = 0b001000
COMPUTE_OPERAND_COUNT["AVGPOOL"] = 2
```

## 6. 参数 COE

文件：

```text
python/params_to_bram_coe.py
```

核心扩展点：

```python
PARAMETER_STAGE_BUILDERS
```

无参数算子不需要注册，脚本会跳过。

参数类算子需要新增 builder，例如：

```python
def generate_xxx_params(layer_plan, tensors, model_params, out_dir):
    # read data/model_params/*.txt
    # pack into hardware layout
    # write coe/<name>_params.coe
```

然后注册：

```python
PARAMETER_STAGE_BUILDERS["xxx"] = generate_xxx_params
```

同时 `generate_memory_plan.py` 中必须为该参数区调用 `add_init_region()`，并在 `plan["tensors"]` 中记录 size/layout。

## 7. 硬件约束检查

约束应尽量放在最接近其来源的位置：

- 前端：检查模型参数能否导出，例如 weight/bias 类型和范围。
- memory plan：检查全局布局、shape、通道对齐、地址大小、拆分策略。
- operator：检查指令位域能否编码，例如矩阵边长是否在寄存器可表达范围内、通道数是否在单次指令范围内。
- assembler：检查汇编语法、寄存器编号、立即数范围。

不要只依赖最后的 assembler 报错。memory plan 应尽早给出更接近模型语义的错误。

## 8. 测试建议

每次新增算子后至少运行：

```bat
python -m compileall .\python .\operator
python .\test\run_regression.py
.\build.bat
```

还应人工检查：

```text
data/model_ir.json
data/memory_plan.json
data/instr.asm
data/instr.txt
target/all.coe.map.txt
```

重点看：

- runtime region 是否连续且不重叠。
- init region 是否包含所有参数和指令。
- 每个 split 的输入/输出地址是否符合硬件布局。
- 指令数量是否等于 `memory_plan["tensors"]["instr"]["size_bytes"] / 4`。
- 边长、通道数、参数大小是否和文档描述一致。
