# 文档索引

本文档用于帮助人工维护者或后续 AI 快速理解当前 NPU 编译器工程。

建议阅读顺序：

1. `编译器整体运行流程说明.md`
   - 了解从模型、图片、参数到最终 `target/all.coe` 的完整构建流程。
   - 适合作为第一次接手工程时的入口。

2. `当前能力与限制.md`
   - 快速确认当前支持哪些网络结构、通道数、stride/padding、数据布局和构建方式。
   - 修改模型或扩展编译器前应先阅读。

3. `NPU_特性与数据排列规则.md`
   - 了解 NPU 数据布局、image/weight/bias COE 排列规则、通道补齐、group 拆分和关键寄存器语义。
   - 当输出结果或地址偏移不对时，优先检查这里的规则。

4. `generate_memory_plan说明.md`
   - 了解 `data/memory_plan.json` 的字段含义。
   - 后续脚本主要依赖该 JSON 中的 tensor、region 和 execution_plan。

5. `generate_instr说明.md`
   - 了解如何从 `memory_plan.json` 和 `intr_move.json` 生成 `data/instr.asm` / `data/instr.txt`。

6. `operator说明.md`
   - 了解 `operator/conv`、`operator/dsmp`、`operator/relu` 如何把单个 op plan 翻译成汇编片段。

7. `assembler说明.md`
   - 了解汇编指令如何编码成 32-bit 机器码。

8. `NPU指令手册.md`
   - 指令编码和寄存器字段的参考手册。
   - 该文件由原 Word 版指令手册转换而来，便于文本检索和 AI 阅读。

核心数据流：

```text
model/*.pth
  -> python/extract_pth_params.py
  -> data/model_params/layerN_0_weight.txt
  -> data/model_params/layerN_0_bias.txt

model/*.py + python/npu_config.py
  -> python/generate_memory_plan.py
  -> data/memory_plan.json

data/memory_plan.json + data/intr_move.json
  -> python/generate_instr.py
  -> data/instr.asm
  -> data/instr.txt

image / weight / bias / instr
  -> *_to_bram_coe.py
  -> coe/*.coe

data/memory_plan.json + coe/*.coe
  -> python/merge.py
  -> target/all.coe
  -> target/all.coe.map.txt
```

当前最重要的事实：

- `memory_plan.json` 是地址规划、shape、group split 和后续指令生成的中心文件。
- 数据在内存中按 4 通道对齐。
- 当前单次 NPU pass 最多处理 8 个输出通道。
- 当前输入通道数大于 4 还不支持。
- `stride=2,padding=0` 会被规划成 `conv(stride=1) -> dsmp -> relu`，bias 由 CONV 自动处理。
- ReLU 配置寄存器中的 image size 写实际 feature map 边长，不像 conv/madd 那样除以 8。
