# 当前能力与限制

本文档记录当前 NPU 编译器和 NPU 数据构建链路的能力边界。

## 1. 模型解析

当前 `python/model_parser.py` 从模型定义 `.py` 中解析 `self.layerN` 里的 `nn.Conv2d`。

会提取：

```text
in_channels
out_channels
kernel_size
stride
padding
```

还会从 `self.layer` 中提取 `LeakyReLU` 的 `negative_slope`，转换成 ReLU 指令中的 `tan` 字段。

当前 `python/npu_config.py` 中：

```text
INFER_PARSE_MODE = 2
INFER_PARSE_LAYER_LIMIT = 3
CHANNEL_GROUP4_FEATURE_SIZE_THRESHOLD = 256 * 256 * 4
```

因此默认只解析前 3 层。若要解析完整模型，需要修改 `INFER_PARSE_MODE`。

## 2. 通道能力

NPU 数据内存布局按 4 通道对齐。

当前单次 NPU pass 最多处理 8 个输出通道。输出通道大于 8 时，`generate_memory_plan.py` 默认按先 8 后 4 的通道 group 拆分；若该层输入或输出 feature map 存储元素数（宽 * 高 * 按 4 对齐后的通道数）大于等于 `CHANNEL_GROUP4_FEATURE_SIZE_THRESHOLD`，则只按 4 通道 group 拆分，例如：

```text
12 output channels -> 8 + 4（未触发阈值）
12 output channels -> 4 + 4 + 4（触发阈值，例如当前 layer2）
16 output channels -> 8 + 8（未触发阈值）
13 output channels -> 8 + 8，其中最后 3 个为有效通道，另外 3 个为补齐通道（未触发阈值）
```

当前输入通道能力：

```text
conv in_channels <= 256: 支持
conv in_channels > 256 : 不支持
conv 之外的算子单次 channels <= 8
```

当卷积层 `in_channels > 256` 时：

- `generate_memory_plan.py` 会报错，不生成可用 memory plan。
- `params_to_bram_coe.py` 也会报错，不生成近似或不完整的参数 COE。

对于 DSMP、ReLU、MADD 等非卷积算子，当前仍按输出通道 group 执行，若单次配置通道数大于 8，operator 会直接报错。

## 3. 卷积 stride/padding

当前支持：

```text
stride = 1
stride = 2, padding = 0
```

`stride = 1` 时执行：

```text
conv -> relu
```

`stride = 2,padding = 0` 时，因为 NPU 卷积单元实际 stride 固定为 1，所以执行：

```text
conv(stride=1) -> dsmp -> relu
```

当前不支持：

```text
stride > 2
stride = 2, padding != 0
```

遇到不支持的 stride/padding 时，memory plan 生成阶段直接报错。

## 4. 数据布局

image:

```text
RGB -> RGB0
pixel0: R, G, B, 0
pixel1: R, G, B, 0
...
```

当前 `build.sh` 暂时不从 jpg/png 等图片生成 `coe/image.coe`，而是直接使用构建前已经存在的 `coe/image.coe`。`python/image_to_bram_coe.py` 仍保留在工程中，后续需要恢复图片转 COE 时可以重新启用。

weight:

```text
原始格式: [out_channel, in_channel, kernel_h, kernel_w]
存储格式: [out_channel, aligned_in_channel, kernel_h, kernel_w]
emit 顺序: oc -> kh -> kw -> ic
```

bias:

```text
bias 个数等于卷积输出通道数，先补 0 到 4 的倍数。
每个 bias 按 signed int32 原样写入 COE，不截位、不按 feature map 展开矩阵。
bias region 紧跟对应 layer 的 weight region，NPU 根据卷积配置寄存器的 bias bit 自动读取。
```

输入通道补齐产生的 0 kernel 必须真实写入 weight COE；输出通道补齐只作用于 feature map、bias 和运行时区域，不再为虚拟输出通道写入整组 0 kernel。

## 5. 配置寄存器尺寸语义

conv 的 image/block 字段写入的是：

```text
feature_width / 8
```

ReLU 和 DSMP 的 image size 字段写入的是实际 feature map 边长：

```text
feature_width
```

这点很重要：ReLU 不需要除以 8。

当前代码状态：

- `operator/conv/conv.py` 使用 `width // 8`。
- `operator/relu/relu.py` 直接使用 `feature_size`。
- `operator/dsmp/dsmp.py` 直接使用 `image_size`。

## 6. 默认地址空间

当前 `python/npu_config.py` 中：

```text
INIT_BASE_ADDR    = 0x00000000
INIT_LIMIT_ADDR   = 0x00200000
RUNTIME_BASE_ADDR = 0x00200000

IMAGE_BASE_ADDR = 0x00000000
IMAGE_SOURCE    = "coe"

IMAGE_HEIGHT = 256
IMAGE_WIDTH  = 256
CHANNEL_GROUP4_FEATURE_SIZE_THRESHOLD = 256 * 256 * 4
```

初始化区包含 image、weight、bias、instr 等需要写入最终 COE 的数据。

运行时区包含 conv/dsmp/relu 的中间输出缓冲区，不直接写入最终 COE。
