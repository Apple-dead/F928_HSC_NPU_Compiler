# 当前能力与限制

## 1. 模型输入

当前编译器只支持 PT2 输入：

```python
MODEL_FORMAT = "pt2"
MODEL_PATH = "./model/Yolov2_0708_ptq_int8.pt2"
```

模型前端入口：

```bash
python ./python/generate_model_ir.py
```

该脚本生成：

```text
data/model_ir.json
data/model_params/
```

旧的 `.py` 模型 AST 解析和 `.pth` 参数提取流程已经从主流程中移除。

## 2. 当前 PT2 前端能力

当前前端支持从 `torch.export.ExportedProgram` 中解析：

```text
aten.conv2d.default
aten.relu.default
aten.leaky_relu.default
aten.avg_pool2d.default
aten.max_pool2d.default
aten.flatten.using_ints
aten.linear.default
```

`clamp/to/floor` 这类量化辅助节点会透传，不写入 IR。`leaky_relu` 会降成 IR 的 `relu`，并保留 `negative_slope/tan`。

可以用 `npu_config.py` 控制解析范围：

```python
INFER_PARSE_MODE = 1      # 全量解析
INFER_PARSE_MODE = 2      # 只解析前 N 个有效 IR op
INFER_PARSE_OP_LIMIT = 1
```

`INPUT_HEIGHT` / `INPUT_WIDTH` 只是 PT2 输入 shape metadata 缺失时的 fallback。正常 PT2 模型如果已经在 graph metadata 中携带输入尺寸，例如 `256x256x3`，则前端和 memory plan 都使用 PT2 metadata 中的尺寸，而不会使用这两个 fallback 值。

limit 按 PT2 图中的可执行有效 IR op 计数，而不是只按卷积层计数。例如：

```text
limit=1 -> conv2d
limit=2 -> conv2d -> relu
limit=3 -> conv2d -> relu -> 下一个有效 op
```

对于 YOLO PT2 这类 `conv2d -> leaky_relu -> floor -> conv2d` 图，`floor` 等辅助节点不计入 limit，但 `conv2d` 和 `leaky_relu` 都会计入。因此 `INFER_PARSE_OP_LIMIT=6` 会导出前三个 conv 及其对应 ReLU。

参数导出规则：

```text
conv weight   -> data/model_params/layerN_0_weight.txt
conv bias     -> data/model_params/layerN_0_bias.txt    # 仅有 bias 时
linear weight -> data/model_params/linearN_weight.txt
linear bias   -> data/model_params/linearN_bias.txt     # 仅有 bias 时
```

weight 必须是 int8 整数，bias 必须是 int32 整数。

## 3. 当前后端能力

当前 memory plan / 指令生成后端支持：

```text
conv2d/relu/avgpool2d/maxpool2d/linear
```

`flatten` 作为透传节点由前端忽略，不进入 `model_ir.json`；`linear` 会在后端展开为多条 FULL 指令。遇到其他暂不支持 op 时，`generate_memory_plan.py` 必须明确报错。

若配置为：

```python
INFER_PARSE_MODE = 2
INFER_PARSE_OP_LIMIT = 2
```

则 IR 只包含 `conv2d -> relu`，可以进入当前后端支持路径。若配置为 `INFER_PARSE_OP_LIMIT = 1`，则只生成 conv 指令，不会自动补 ReLU。

## 4. Conv 截位配置

conv 截位配置由根目录 `intr_move.json` 提供，路径由 `npu_config.py` 指定：

```python
INTR_MOVE_PATH = "./intr_move.json"
```

配置字段为：

```json
{
  "CONV_MOVE_BY_INDEX": {
    "1": 512,
    "2": 64,
    "3": 256
  }
}
```

`CONV_MOVE_BY_INDEX` 表示当前 IR 中第 N 次 conv 的 move，从 1 开始。它不绑定 `layerN` 名称，因此在 `INFER_PARSE_OP_LIMIT` 改变时仍按当前参与编译的 conv 顺序生效。

## 5. 无 bias Conv2d

当前已经支持无 bias conv：

```text
IR: has_bias=false, bias_file=null
memory_plan: 不创建 layerN_bias tensor
params_to_bram_coe.py: 不读取 bias txt，不写 bias，不补 0 bias
generate_instr.py/operator/conv: RCONV condition_bias bit = 0
```

有 bias 时仍沿用原物理布局：

```text
每个 group = valid weights + padded int32 bias
```

无 bias 时布局为：

```text
每个 group = valid weights
```

## 6. 通道能力

- NPU 数据内存布局按 4 通道对齐。
- 单次 NPU pass 最多处理 8 个 conv 输出通道；当输入或输出 feature map 存储元素数达到 `CHANNEL_GROUP4_FEATURE_SIZE_THRESHOLD` 时，conv 输出通道按 4 通道 group 拆分。
- conv 的输入通道字段按实际输入通道数配置，范围为 1 到 256，不按 channel group 拆分；conv 只拆分输出通道。
- ReLU 和 DSMP 的输入通道字段均支持 1 到 256 通道，编译器按实际输入通道数配置，不再按 conv channel group 拆分。
- AVGPOOL/MAXPOOL 的输入通道字段按完整输入 storage channels 配置，单条池化指令覆盖完整输入通道，不再按 4 通道拆分；输入 storage channels 必须是 4 的倍数，否则 memory plan 报错。
- runtime feature map 的 H/W 至少按 8x8 预留，且按 8 的倍数对齐；各算子配置指令时也会检查对应 feature size 是否能被 8 整除。

## 7. stride / padding

当前支持：

```text
stride = 1
stride = 2, padding = 0
```

`stride = 1`：

```text
conv -> relu
```

`stride = 2,padding = 0`：

```text
conv(stride=1) -> dsmp -> relu
```

当前不支持：

```text
stride > 2
stride = 2, padding != 0
dilation != 1
groups != 1
```

## 8. 数据布局

image：

```text
RGB -> RGB0
```

weight：

```text
原始逻辑格式: OIHW
物理格式: oc -> 每 4 个输入通道一组 -> kh -> kw -> 组内 ic
```

bias：

```text
仅有 bias 时写入参数区，按 int32 word 保存，并按 group 补到 4 通道边界。
```

runtime feature map：

```text
通道按 4 对齐，H/W 按至少 8x8 且为 8 的倍数预留。
```


## AVGPOOL / MAXPOOL 当前限制

当前 AVGPOOL / MAXPOOL 专用指令由编译器配置输入矩阵边长和输入通道数，NPU 根据输入通道数一次处理完整输入通道，不再由编译器按 4 通道拆分。

输入 storage channels 仍必须是 4 的倍数，否则 `generate_memory_plan.py` 会报错。

当前 AVGPOOL / MAXPOOL 指令语义固定为：

```text
kernel_size = [2, 2]
stride      = [2, 2]
padding     = [0, 0]
dilation    = [1, 1]
ceil_mode   = False
```

其他池化配置会在 `generate_memory_plan.py` 阶段报错。
