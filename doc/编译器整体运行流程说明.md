# 编译器整体运行流程说明

## 1. 文档目的

本文档说明当前 NPU 编译器从 PT2 模型出发，生成标准 IR、标准参数文件、memory plan、NPU 指令和最终 BRAM 初始化 COE 的主流程。

当前模型输入已经统一为 PT2：

```python
MODEL_FORMAT = "pt2"
MODEL_PATH = "./model/Yolov2_0708_ptq_int8.pt2"
```

旧的 `model.py + model.pth` 解析和参数提取流程不再属于主构建路径。

## 2. 目录职责

```text
python/frontend/
```

模型前端。当前包含 PT2 frontend，负责读取 `torch.export` 模型、解析推理图、导出标准 IR 和标准参数文本。

```text
data/
```

存放构建中间产物：

```text
data/model_ir.json
data/model_params/
data/memory_plan.json
data/instr.asm
data/instr.txt
```

```text
python/
```

主流程脚本：

```text
generate_model_ir.py
generate_memory_plan.py
generate_instr.py
params_to_bram_coe.py
instr_txt_to_bram_coe.py
merge.py
```

```text
operator/
```

单个 NPU 算子的汇编生成规则：

```text
operator/conv/conv.py
operator/dsmp/dsmp.py
operator/relu/relu.py
```

```text
coe/
```

存放各初始化区的 COE 文件。预置输入数据的 COE 路径由 `npu_config.py` 中的 `IMAGE_PATH` 指定。

```text
target/
```

最终产物：

```text
target/all.coe
target/all.coe.map.txt
```

## 3. 构建入口

Linux / Git Bash / WSL：

```bash
./build.sh
./build.sh clean
./build.sh distclean
```

Windows cmd：

```bat
.\build.bat
.\build.bat clean
.\build.bat distclean
```

当前 `build` 主流程为：

```text
python ./python/generate_model_ir.py
python ./python/generate_memory_plan.py
python ./python/generate_instr.py
python ./python/params_to_bram_coe.py --memory-plan ./data/memory_plan.json --model-params ./data/model_params --out-dir ./coe
python ./python/instr_txt_to_bram_coe.py ./data/instr.txt ./coe/instr.coe
python ./python/merge.py --memory-plan ./data/memory_plan.json ./target/all.coe
```

`clean` 会删除构建产物和临时回归产物：

```text
data/model_ir.json
data/model_params/
data/memory_plan.json
data/instr.asm
data/instr.txt
data/tmp_regression/
coe/layer*_params.coe
coe/instr.coe
target/all.coe
target/all.coe.map.txt
__pycache__/
```

`clean` 不删除模型、配置和输入数据，例如 `model.pt2`、`intr_move.json`、`IMAGE_PATH` 指向的输入 COE。

`distclean` 会先执行 `clean`，再删除回归测试错误日志：

```text
test/error/*.log
test/error/*.log.txt
test/error/*.txt
```

## 4. 总体流程

```text
model.pt2
  -> generate_model_ir.py
  -> data/model_ir.json
  -> data/model_params/*.txt

data/model_ir.json
  -> generate_memory_plan.py
  -> data/memory_plan.json

data/memory_plan.json + intr_move.json
  -> generate_instr.py
  -> data/instr.asm
  -> data/instr.txt

data/model_params + data/memory_plan.json
  -> params_to_bram_coe.py
  -> coe/layerN_params.coe

data/instr.txt
  -> instr_txt_to_bram_coe.py
  -> coe/instr.coe

data/memory_plan.json + coe/*.coe
  -> merge.py
  -> target/all.coe
```

## 5. 阶段一：PT2 前端

脚本：

```text
python/generate_model_ir.py
```

输出：

```text
data/model_ir.json
data/model_params/layerN_0_weight.txt
data/model_params/layerN_0_bias.txt    # 仅有 bias 时存在
data/model_params/linearN_weight.txt
```

可以通过 `python/npu_config.py` 控制解析范围：

```python
INFER_PARSE_MODE = 1      # 完整解析
INFER_PARSE_MODE = 2      # 只解析前 N 个有效 IR op
INFER_PARSE_OP_LIMIT = 6
```

量化辅助节点如 `clamp/to/floor` 会透传，不计入 limit。

## 6. 阶段二：memory plan

脚本：

```text
python/generate_memory_plan.py
```

输入：

```text
data/model_ir.json
python/npu_config.py
IMAGE_PATH 指向的输入 COE
```

该阶段只从标准 IR 读取模型结构，不再读取模型定义 `.py` 文件。`IMAGE_SOURCE = "coe"` 时，输入 COE 路径由 `IMAGE_PATH` 指定。当前后端支持 `conv2d/relu/avgpool2d/maxpool2d/linear` 路径；如果 IR 中出现其他暂不支持的 op，会直接报错。

memory plan 会为每个参与编译的 conv 写入 `conv_index`。它表示当前 IR 中第几次 conv，从 1 开始，用于后续指令生成查截位配置。

## 7. 阶段三：指令生成

脚本：

```text
python/generate_instr.py
```

输入：

```text
data/memory_plan.json
intr_move.json
operator/
```

`intr_move.json` 的路径由 `npu_config.py` 指定：

```python
INTR_MOVE_PATH = "./intr_move.json"
```

截位配置使用：

```json
{
  "CONV_MOVE_BY_INDEX": {
    "1": 512,
    "2": 64,
    "3": 256
  }
}
```

这里的编号是当前 IR / 当前编译图中的 conv 顺序，不是 `layerN` 名称。`generate_instr.py` 从 `memory_plan.execution_plan` 读取每个 split 的 conv / dsmp / relu 地址和尺寸，并把 `split.conv.has_bias` 传给 `operator/conv/conv.py`。

## 8. 阶段四：参数 COE

脚本：

```text
python/params_to_bram_coe.py
```

有 bias 时，每个 group 的物理布局为：

```text
valid weights + padded int32 bias
```

无 bias 时，每个 group 的物理布局为：

```text
valid weights
```

无 bias 时脚本不会读取 bias txt，不会写 bias，也不会补零 bias。

## 9. 阶段五：指令 COE 与最终合并

```text
instr_txt_to_bram_coe.py
  data/instr.txt -> coe/instr.coe

merge.py --memory-plan data/memory_plan.json target/all.coe
  按 memory_plan.init_regions 顺序合并 image、params、instr
```

`merge.py` 对输入 COE 的初始化 token 采用严格解析：裸 token 一律按
该文件头部的 `memory_initialization_radix` 解释。当前主流程生成的 COE
均为 `memory_initialization_radix=16`，所以 `0D010413` 这类 word
会按十六进制保留。合并脚本不再支持 Python 风格 `0x`/`0b`/`0d`
前缀，也不支持 Verilog 风格 `32'h...`/`32'b...`/`32'd...` 前缀。

最终 map 文件用于检查合并地址是否与 memory plan 一致：

```text
target/all.coe.map.txt
```
