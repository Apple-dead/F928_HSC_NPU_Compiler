# 全编译器统一的 8 通道分组布局（2026-11-05）

所有带空间和通道维的 NPU 数据统一按 **通道组 → 行 → 列 → 组内 8 通道** 排列。通道数补齐到 8 的倍数只是容量计算，还必须按组排列数据。

例如 H×W×16 的物理顺序是：

```text
ch1..8:   (h0,w0), (h0,w1), …, (hH-1,wW-1)
ch9..16:  (h0,w0), (h0,w1), …, (hH-1,wW-1)
```

采用从 0 开始的 h、w、c 下标时，字节偏移为：

```text
(c // 8) * H * W * 8 + (h * W + w) * 8 + c % 8
```

最后一组不足 8 个通道时，各像素的剩余 lane 补零。例如 9 通道会存一整块 H×W×8，再存一整块 H×W×8，其中第二块每像素只有第一个 lane 有效。

`python/memory_layout.py` 中的 `FEATURE_LAYOUT` 是统一布局定义，`pack_feature_hwc` 可把逻辑 HWC 原始字节转成该布局。图像转换使用这个打包入口。普通图像模式最多只有 4 个通道，只占一组，因此 L/RGB/RGBA 的现有数据字节顺序不变。外部输入和输入 COE 也必须采用此布局；仅从 COE 长度无法识别内容采用了哪一种通道顺序。

CONV、融合 ReLU、AVGPOOL、MAXPOOL、DSMP、USMP 的特征图和模型输出使用相同布局。CONV 单次最多 8 个输出通道，需要多次下发；其他算子的寄存器仍可配置全部有效通道，硬件按组读取和写回，通道分组并不等于所有算子都只能配置 8 通道。

CONV 权重在每个有效输出通道内部按输入通道组 → kernel H → kernel W → 8 lane 排列，后接可选的 int32 小端 bias 和 4 个零字节；不增加无效输出参数记录。FULL 权重在每个输出神经元内部按输入通道组 → H → W → 8 lane 排列，与图像、池化、采样或卷积提供的输入顺序一致；不再保留逐像素排列全部输入通道的分支。FULL 输出是一维神经元向量，没有空间维，按输出神经元顺序存放；bias 同样没有空间维。

通道维 cat 可以把完整 8 通道组直接连续放置，因此不再限制 H×W=1。前面的输入段必须没有通道补齐，最后一段可以不足 8 通道并补齐到 8；例如 16+8、8+5 可直接拼接。5+8 会在中间留下 padding，必须重排数据，当前后端对此明确报错。

旧的 downsample/upsample 示例参考输出仍保留逐像素全通道排列，按用户要求暂不修改或重新生成。它们不是当前编译器的布局规范。

此前的软件回归验证覆盖了多空间位置的 9/16/17 通道字节序及补齐、CONV 权重、FULL 权重与点积等价性、池化/采样/CONV/FULL 串联、模型输出布局和 cat 地址。验证限于编译器与软件参考，未执行 RTL 仿真。
